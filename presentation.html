1. Introduction — Why LLM Agents for Cybersecurity?

🚨 The Problem

  • Modern vehicles = 100M+ lines of code, connected ECUs, V2X
  • In-vehicle LLM assistants deployed (BMW IPA, VW IDA, Mercedes MBUX)
  • Google A2A protocol authenticates senders, not content
  • New threat class: compromised-but-authenticated agents inject arbitrary payloads
  • ISO/SAE 21434 demands continuous automated threat monitoring
  • Driver cognitive load effects last 27+ seconds after interaction

💡 Our Approach

  • Static-first: Deterministic regex/heuristics always run — LLM refines, never invents
  • Multi-agent: Specialized agents for code, logs, topology
  • Dual-mode: Both defense AND red-team attack simulation
  • MCP-driven: Typed tool registry with dry-run, rollback, audit
  • Guard-enforced: 4 contextual security checks on every action

Adaptive Re-Planning (Paper 5, pipeline.py)

  • Closed loop: detect → decide → act → observe → re-decide
  • Max rounds: configurable (max_replan_rounds: 2)
  • Escalation: if plan fails/refused, tier bumps one notch up
  • Feedback: prior_tier, plan_status, guard_reason fed back to DecisionAgent
  • Memory-aware: Decision Agent recalls K=5 similar past incidents (Jaccard)
  • Cross-session: "similar incident resolved with tier X" → adopt
  • Terminal: stops when plan succeeds OR max rounds reached
for round in range(1, max_rounds+1): decision = decision_agent.run(results, feedback=feedback) action = action_generator.generate(decision, code) verdict = guard.check(action, objective, inputs) trajectory = guard.check_trajectory(plan.steps) if success or round == max_rounds: break feedback = {prior_tier, plan_status, reason} # escalate

LLM as Tool Selector (generator.py)

Deterministic playbook is the floor; LLM can only ADD tools — never bypass safety.

TOOL_SELECT_PROMPT: "A deterministic playbook has chosen the core steps. Propose ADDITIONAL tool calls that strengthen the response. Available MCP tools: [catalogue] ← registry.schemas() Return JSON: {tools: [{tool, kind, params, why}]}"
  • Validated: each pick checked against tool's JSON schema
  • Registered: only tools in MCPRegistry accepted
  • Guarded: per-step SecurityGuard runs on every LLM-selected step
  • Tagged: rule_id="LLM-SELECTED" for audit trail
  • Safe fallback: parse failure → empty list (best-effort)

3. Decision Agent + Signed Memory Store

agents/decision_agent.py

Uses reasoning LLM (GPT-4o, temp=0). Now memory-aware + re-planning-aware.

Prompt Template (updated)

"You are the central decision agent... Aggregated findings: [findings] Similar past incidents recalled from signed memory (paper 5 adaptive learning): [memory] Cross-session recommendation (what worked): [recommendation] Feedback from previous attempt this run: [feedback] Decide: categories, tier, confidence, justification → JSON"

Policy on Top of LLM

  • Escalation: if prior tier failed → bump one notch up
  • Memory: similar incident worked at tier X → adopt (only escalate, never downgrade)
  • Heuristic: top asset category propagated to highest-severity findings

Signed Memory Store (memory_store.py)

SQLite + HMAC-SHA256 — no new dependencies.

  • E.1: One row per incident, including plan_status + remediation_ok
  • E.2: recall_similar(rule_ids, k=5) — Jaccard overlap of rule-id sets
  • E.3: Every write HMAC-signed with per-deployment key; reads verify signature + source
  • Poison defense: unauthenticated source → MemoryAuthError (paper 1/2)
  • Cross-session: recommend() → "tier X worked on similar incident"
# Write (E.3) memory.record(Incident( mode, scenario, rule_ids, tier, confidence, action_kind, guard_allowed, plan_status, remediation_ok, # did it WORK? source="rules_engine" # authenticated )) → HMAC-sign canonical fields → INSERT # Read (E.2) memory.recall_similar(rule_ids, k=5) → Jaccard(query_rule_ids, row_rule_ids) → verify_row(signature, source) → ranked list of Incident(similarity=...)

3. MCP Tool Design — Two Layers

Layer 1: Action-Engine Registry (agents/action_engine/mcp_tools.py)

20+ schema-validated, audited tool subclasses used by the executor:

  • MCPTool base: validate() → call() → verify()
  • SideEffect enum: READ | WRITE | DESTRUCTIVE
  • real_available() checks shutil.which(binary)
  • Dry-run default: status="would-execute" + payload preview
  • Audit: every call appended to registry.audit[]

Layer 2: Real MCP Tools (tools/mcp_tools.py)

Lightweight run()-style entry point with real backends:

ToolReal BackendSafety
PortScanToolnmap -sT or pure-Python TCP connectdry-run default
StaticAnalysisToolbandit -f json or semgrep --jsonread-only, always runs
PacketCaptureTooltshark / tcpdump / candumpdry-run default
  • All subprocess: explicit args=[...], never shell=True
  • Bounded timeout=60s (120s for scans)
  • Active tools default to live=False → dry-run envelope
  • Falls back gracefully if binary not installed

MCPTool Base Class

class MCPTool: name: str # "firewall.block_ipv4" side_effect: SideEffect requires_authorization: bool real_binary: str | None schema: list[MCPSchemaField] domain: str # firewall|network|... dry_run: bool = True def validate(params) → list[str]: # schema check (type, required, enum) def call(params) → ToolResult: if dry_run or not real_available(): return self._dry_run(params) return self._do_call(params) def verify(params, result) → bool: # post-condition hook

Real Example: PortScanTool

class PortScanTool: name = "port_scan" def run(target, ports, live=False): if not live: return {dry_run: True, would_run: "nmap -sT -Pn -p ..."} if shutil.which("nmap"): _, out, _ = _run(["nmap","-sT","-Pn", "--open","-p",ports,"-oG","-",target]) return {backend:"nmap", open_ports:[...]} # Fallback: pure-Python TCP connect for p in COMMON_PORTS: socket.connect_ex((host, p)) return {backend:"socket", open_ports:[...]}

TOOL_REGISTRY

Global dict: {PortScanTool, StaticAnalysisTool, PacketCaptureTool} — importable by any module needing quick tool access.

3. Security Guard + Ha Judge + Trajectory Checks

Three Enforcement Levels

1. Final Action Check (guard.check())

4 properties on the translated Action. Coarse static map is the floor.

2. Per-Step Check (guard.check_step())

Runs on every MCP tool call via GuardAdapter. Uses real side_effect + requires_authorization from step (not a hard-coded kind list).

3. Trajectory Check (guard.check_trajectory())

Evaluates the sequence for compositional + temporal violations:

  • F.3 Compositional: exfil chain (read sensitive → external egress), destructive without snapshot, destructive without notify
  • F.4 Temporal: TOCTOU (precondition with no postcondition), memory-poisoning (destructive plan fed by memory input)

Ha Judge (ha_judge.py)

Separate LLM call: "does action A serve objective O in context C?" Paper 1 shows this cuts ASR by 86-88%.

  • Independent model call — subverting scanners still needs to pass judge
  • Can only tighten — never loosens the deterministic floor
  • Per-instance memoisation (same question = one call)
  • Deterministic fallback: refuses privileged action under report-only objective

Guard Code Flow

SecurityGuard.check_step(step, objective, inputs): # 1. Task alignment task_ok = objective in allowed_objectives # 2. Action alignment + H_a judge static_ok = kind ∈ compatible_set(objective) if static_ok AND ha_judge: ctx = f"tool={step.tool}; rule_id=...; side_effect=...; threat=..." serves, reason = ha_judge.judges( kind, objective, ctx) if not serves: action_ok = False # 3. Source authorization privileged = (side_effect=="destructive" OR requires_authorization) source_ok = (not privileged) or has_auth # 4. Data isolation isolation_ok = dest ∈ trusted_destinations → StepVerdict(allowed, reasons)
SecurityGuard.check_trajectory(steps): # F.3 Compositional if reads_sensitive AND external_egress: → "possible exfil chain" if destructive AND no forensic snapshot: → "no evidence preservation" if destructive AND no notify: → "no human in the loop" # F.4 Temporal if contain/eradicate + pre but no post: → "TOCTOU risk" if destructive + memory-sourced input: → "memory-poisoning risk" → TrajectoryVerdict(compositional_ok, temporal_ok)

5. Limitations

🤖

LLM Limitations

  • StubLLM returns keyword-matched canned JSON — cannot detect novel patterns
  • Real LLM (GPT-4o) wired but requires API key + network
  • Token budget warns but doesn't block — no RAG chunking yet
  • LLM can hallucinate findings — mitigated by static-first merge
  • Ha judge is probabilistic — conservative fallback to heuristic on parse failure
  • LLM tool selector is best-effort — parse failure → empty list
🔧

MCP Tools — Dry-Run Default

  • Firewall tools need root/admin — rarely available in dev
  • network.isolate_node is a connector stub (no real SDN)
  • runtime.safe_mode is a connector stub (no real ECU)
  • Port scan/packet capture require live=True + installed binary
  • No SOAR/SIEM integration (Splunk/XSOAR would need connector)
  • Vehicle-specific tools (CAN-utils, ECU flash) are stubs
📏

Detection Coverage

  • Code scanner: regex-based — cannot detect logic vulnerabilities or obfuscated code
  • Log analyzer: 8 hand-coded heuristics — no ML-based anomaly detection
  • Deployment scanner: YAML-specific format — won't work on arbitrary configs
  • Languages limited to Python, C, C++ (no Java, Go, Rust)
  • Rules manually authored — no automatic CVE-to-rule pipeline
🔄

Architecture Gaps

  • Re-planning limited to 2 rounds — no infinite escalation
  • Memory recall is Jaccard-only — no embedding/semantic similarity
  • Batch processing only — no real-time streaming / event-driven mode
  • Single-process — no distributed edge deployment
  • Trajectory checks are heuristic — not formal verification
  • Attack scripts use benign canaries only — no real exploitation

  • Per-Step Guard: 4 properties checked on every tool call + Ha
